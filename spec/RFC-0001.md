# RFC-0001: GMB — Gate Mutation Benchmark

**状态**：Draft v0.1（可实施草案）
**日期**：2026-11-16
**署名**：GMB-protocol contributors（组织署名，非个人）
**.About**：一份给「验收门禁 / 自动评审器 / LLM-as-judge / 交付检查器」做**有效性体检**的开放协议。本 RFC 定义术语、强制字段、实验纪律与判定三态；不定义任何具体门禁的实现。

---

## 0. 一句话（费曼层）

给 AI 打分很容易，**证明打分器本身没在自欺**很难。GMB 规定了一套人人可复跑的体检流程：拿两组题去考同一个门禁——一组出题人自己知道答案（自设计集），一组由第三方在不知判据的情况下出（独立集）。如果它对自出题 100 分、对独立题 0 分，这个门禁就是"背答案"，不是"有能力"。整套流程的口径必须在看结果**之前**锁死，否则又是一轮自证。

## 1. 问题定义（Problem）

### 1.1 现象
一个验收门禁 G、一份被测文档 D。G 对 D 报 PASS，只能证明"D 通过了 G 的判据"，**不能证明**"G 的判据与 D 的真实质量有任何关系"。当前 eval 生态（promptfoo 27,294★、langfuse、deepeval、ECC harness 等）几乎全部停在"报分数"层，把门禁当可信前提，而非被检验对象。

### 1.2 本协议要回答的唯一问题
> **G 的检测力，有多少是真的，有多少是对自设计缺陷的过拟合？**

### 1.3 范围外（明确不解决的问题）
- 不定义 D 的质量真值从何而来（由 §4 的 oracle 提供方负责）。
- 不证明 G 的语义正确性；GMB 只量化"已知缺陷的检出率"与"统计边界"。
- 不构成对任何系统的安全认证或法律意见。

## 2. 术语（Normative）

| 术语 | 定义 |
|---|---|
| **Gate (G)** | 任一返回 PASS/FAIL（或多级 verdict）的自动判定器，输入为 artifact A。 |
| **Artifact (A)** | 被判定的对象（文档、代码、prompt、卷宗、交付物）。 |
| **Defect sample (Dᵢ)** | 一个已知"应被检出"的 A 变体，带缺陷类别 `defect_class` 与难度级 `difficulty_grade`。 |
| **Benign sample (Bⱼ)** | 一个已知"不应报警"的 A 变体。 |
| **Self-designed set (S_self)** | 由 G 的判据设计者或其同框架成员生成的缺陷样本集。 |
| **Independent set (S_indep)** | 由**未接触 G 判据源码**的第三方生成的缺陷样本集，或由真实历史事故回放构成。 |
| **Oracle** | 独立于 G 的标注来源，给出每个样本"应 PASS/FAIL"的期望标签。 |
| **TPR** | 真阳性率 = 检出缺陷数 / 缺陷总数。 |
| **FPR** | 假阳性率 = 误报良性数 / 良性总数。 |
| **Δ（coupling delta）** | `TPR(S_indep) − TPR(S_self)`。**负值越负，过拟合越重**（Δ=−1.0 即独立集全漏、自设计集全过）。此方向为本协议自举案例所采用，负值指示过拟合方向。 |
| **Coverage scope** | 本次实验闸的作用域声明（哪些闸计入、哪些排除、为什么）。 |

## 3. 强制实验纪律（Must，缺一不可）

以下七条是本协议的"红牌"，违反任一条则报告**不得**标注为 GMB-conformant：

1. **Criterion-before-evidence**：`coverage_scope`、排除集、阈值、样本量下限、判定档位必须在运行 G 之前写入锁定的 `protocol.json`，并给出 sha256。
2. **Negative control**：必须包含已知应通过的良性样本；FPR 不可沉默（不报 FPR 的报告无效）。
3. **Independence declaration**：`S_indep` 的生成过程必须以书面形式声明独立程度（强独立＝第三方盲设计；弱独立＝历史事故回放；自设计＝不算独立）。**禁止把 S_self 当 S_indep 报**。
4. **No gate added**：跑独立集期间禁止为独立集新增任何闸（防"看着答案补规则"）。
5. **Interval reporting**：任何 TPR/FPR 必须带置信区间（推荐 Wilson 95% 或 Clopper–Pearson），不得只报点估计。
6. **Δ mandatory**：必须同时报 `TPR(S_self)` 与 `TPR(S_indep)` 及 Δ；只报其中一组视为无效。
7. **Four non-claims**：报告不得出现以下四种宣称——①总体逃逸率 ②TPR≥0.9 的通用断言 ③FPR<5% 的通用断言 ④用例相互独立（除非有独立性证明）。

## 4. 证据卡 schema（GMB-Receipt）

一次合规实验产出的回执必须包含以下字段（JSON，`schema/gmb_receipt.schema.json` 为机器可读定义）：

```json
{
  "gmb_version": "0.1",
  "protocol_sha256": "<§3.1 锁定文件的 sha256>",
  "gate_id": "string",
  "run_at": "ISO-8601",
  "criterion_before_evidence": true,
  "coverage_scope": {
    "gates_included": [],
    "gates_excluded": [],
    "exclusion_reason": "string"
  },
  "independence_definition": "strong | weak | self",
  "no_gate_added": true,
  "self_set":  { "n": 0, "TPR": 0.0, "wilson95": [0, 0] },
  "indep_set": { "n": 0, "TPR": 0.0, "wilson95": [0, 0] },
  "coupling_delta": 0.0,
  "benign_set": { "n": 0, "FPR": 0.0 },
  "verdict": "PASS | PARTIAL | FAIL",
  "verdict_basis": "string",
  "four_non_claims_respected": true
}
```

### 4.1 判定三态（阈值须在 §3.1 锁定）

| 态 | 条件（默认建议，可被协议文件覆盖） |
|---|---|
| **PASS** | `TPR(indep)` 下界 ≥ τ_pass 且 `FPR` 上界 ≤ φ 且 `¦Δ¦` ≤ δ_max |
| **PARTIAL** | 结构可复跑、但 `TPR(indep)` 下界 < τ_pass（功率不足或确实无效，二者不分） |
| **FAIL** | negative control 未过 / 违反任一红牌 / 报了禁用宣称 |

> Δ 取绝对值比较（过拟合不论方向）；报告本身保留负号以指示方向。

**关键**：`PARTIAL` 是"不可断言"的一等公民结论，不是 PASS 的委婉说法。

## 5. 参考实现与自举证据（Informative）

本协议的参考实现来自一份能力证明卷宗（已脱敏，内部），其 hold-out 验证记录是一次**真实发生**的 GMB 实验：

- `no_gate_added = true`，`criterion_before_evidence` 由 `scope_note` 明示"口径先定后测"
- `independence_definition = weak`（历史事故回放 + 语义腐化，同作者同框架，如实声明）
- `TPR_all = 1.0`（Wilson [0.7575, 1]）、`TPR_semantic = 0.0`（Wilson [0, 0.2425]）
- `FPR_semantic = 0.0`、negative control PASS
- `coupling_delta = −1.0`（= TPR(indep) 0.0 − TPR(self) 1.0，R4 自设计 → hold-out，同闸不同样本源）

**这条 −1.0 是本协议的核心motivating case**：它证明"门禁总体有效"是站不住的宣称，能站住的只有"对结构破坏类有效、对语义腐化类在独立分布上未证明有效"。

## 7. 可证伪条件（Falsifiability）

本协议在以下任一条件成立时**自我作废或收窄**，须走 verdict-backfill，不得静默：
- F1：出现任一已发布协议，对"文档/报告/agent 交付级验收判据"做变异-保持测试并报独立集区间 → 本协议 novelty 作废，转为向其贡献 adapter。
- F2：promptfoo/deepeval/langfuse 任一内建"双集 TPR + Δ + 三态判定" → 协议价值降为方法论引用。
- F3：第三方用本协议复跑，其 Δ 与本报告同号同量级（持续 >0.5）→ "过拟合普遍存在"命题坐实；若三方 Δ 均 ≈0（普遍不过拟合）→ 体检是伪需求，本协议降级为普通测试规范。
- F4：受审方在看到样本后 48h 内无法对任一 FAIL 提出有效申诉 → 说明 oracle 不可争议性不足，须引入仲裁层。

## 8. 商业与双赢带

- **谁付钱**：需要向客户出具"我们的验收门禁可信"报告的 AI 服务商 / 评测机构 / 甲方验收代理（M46 是本协议的下游变现件）。
- **最小可卖单元**：一份对某团队自有门禁的 GMB 体检报告（含 Δ 与区间）。
- **上游回馈**：向 promptfoo assertion 层提 adapter PR（双集变异算子）；向 KernelAudit 作者投跨域用例引用。
- **成本/风险**：独立集设计 2–3 人日/次（人力不杠杆，须靠协议化+工具化压降）；最大风险是生态不采纳。

## 9. 已知边界（如实）

- n=12 的弱独立样本只给 TPR 单侧 95% 下界 0.873 / 语义 TPR 上界 0.2425，**不证明**总体检测力。
- 本协议测的是"判据对已知缺陷的敏感度"，不是"判据本身的正确性"。
- 语义类 oracle 标注存在主观性；标注者间一致性未量化。
- 单一案例（n=1 系统）自举，须第三方复跑才成立（见 F3）。
